# Generated CLI reference and help-tree golden test

**Date:** 2026-10-05

## Summary

`docs/cli-reference.md` was hand-written and had drifted: seven root commands
and several subcommands were undocumented, and some signatures were wrong. It is
now generated from the cobra command tree, so it cannot drift from the binary,
and CI fails when the committed copy is stale. A golden test pins
`pudl help --json`, so every change to the CLI surface appears as a reviewable
diff.

## Design

- **Two sources.** Everything a command declares (usage line, short and long
  descriptions, examples, flags, subcommands) comes from the command tree.
  Semantics that do not belong in `--help` (exit-status tables, the status
  lifecycle, replay and credential caveats, `--only` selector rules, apply
  budgets) live in hand-written notes under `docs/cli/notes/`, one Markdown file
  per command path (`run_set.md` for `pudl run set`, `_intro.md` for the
  preamble). Notes are included verbatim after their command's generated
  section.
- **Stale notes fail.** A notes file that names no documented command is an
  error, so notes cannot outlive their command.
- **Flags.** Root persistent flags are documented once under "Global flags".
  Each command lists its own flags plus those inherited from a non-root parent
  (for example `--mu-timeout` on `run set`). Hidden and deprecated flags and
  commands, and cobra's lazily-added `help` flag, are omitted.
- **Determinism.** Output is sorted by command and flag name. The
  `facts add --source` default was the only environment-dependent default (the
  OS username, computed at init); it now defaults to empty and resolves to the
  current user at run time, with unchanged behavior.
- **Markdown safety.** Long descriptions render in `text` fences (they contain
  `<placeholders>`). Table cells escape pipes, and escape angle brackets only
  outside backtick code spans.

## Public API

- `cmd.RootCommand() *cobra.Command` — the assembled tree, including cobra's
  default completion command, for tools that document the CLI without running
  it.
- `internal/clidocs`: `Render(root *cobra.Command, notes fs.FS) ([]byte, error)`,
  `NoteName(*cobra.Command) string`, and the constants `ReferencePath`,
  `NotesDir`, `IntroNote`, `Header`.
- `internal/clidocs/gen` — `go run ./internal/clidocs/gen` writes the
  reference; `-check` exits non-zero if it is stale. Wired via `//go:generate`
  in `internal/clidocs/doc.go`, `make docs`, `make check-docs` (also part of
  `make ci`), and a CI step next to the skills check.

## Other changes

- `pudl help --json` no longer includes cobra's `help` flag, which cobra adds
  lazily to commands that have executed, so the tree no longer depends on
  process history.
- `pudl import`'s usage line is now `import [--path <file|dir|pattern>]`,
  reflecting stdin and directory import.
- README command tables gained the missing commands (snapshot, reclassify,
  model new/deps/populator, rule new, guide/prime) and correct signatures.

## Tests

- `internal/clidocs/render_test.go`: sections, global-flag deduplication,
  inherited flags, hidden flags and commands, note placement, stale-note
  rejection, cell escaping, determinism, and `TestCLIReferenceInSync` against
  the committed reference.
- `cmd/help_golden_test.go`: `TestHelpJSONGolden` against
  `cmd/testdata/help.golden.json`; regenerate with
  `go test ./cmd -run TestHelpJSONGolden -update`. It runs in an isolated
  workspace because executing the root command resolves the shared workspace
  policy from the working directory.
