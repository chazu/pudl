# Run core: explicit options, shared finalization, detailed exit codes

Date: October 5, 2026.

Three changes to the `pudl run` / `pudl run set` path, committed separately.

## Explicit run options instead of global flag mutation (refactor)

`pudl run set` drove each member by calling `runCmd.RunE` with the *set*
command, after saving and overwriting 14 package flag variables
(`configureMemberRunGlobals`) and publishing the coordinator through a global
(`activeRunSet`). `pudl run resume` likewise overwrote flag globals
(`restoreApprovalRequest`) and re-entered `runCmd.RunE`. The mu subprocess seam
was a swappable package variable (`runMuRunnerFactory`), contradicting the
seam's own documentation.

Every run is now built from one `runOptions` value and executed with
`executeRun(opts, deps)`:

- `runOptions` embeds `runFlags` and adds the model, mu root, ad-hoc populate
  spec, upstream check, approval/resume fields and observation-age policy. The
  `*Set` booleans replace every `cmd.Flags().Changed` call outside
  `runOptionsFromFlags`.
- Constructors: `runOptionsFromFlags(cmd, args)`, `memberRunOptions(model,
  runSetOptions)`, `resumedRunOptions(runID, approvalRequest)`.
- `runDeps{mu muRunner; set *runSetExecutionContext}`; `defaultRunDeps()` is
  the production wiring. The set context's accessors are nil-safe methods, so a
  standalone run passes a nil set.
- `executeRunSet(models, runSetOptions, runDeps)` and
  `resumeOperation(operationID, runDeps)` replace the cobra handlers as the
  entry points tests drive. The run-set context carries `mu` into mutation
  planning and `executePreparedMutationPlan(db, mu, ...)`.
- Removed: `activeRunSet`, `configureMemberRunGlobals`,
  `restoreApprovalRequest`, `runMuRunnerFactory`, the `runResumeID` and
  `runApprovalStatus` globals.
- `cmd/run.go` (996 lines) split into `run.go` (command and flags),
  `run_options.go`, `run_execute.go` (model resolution and phases),
  `run_conclude.go` (finalization and verdict helpers), `run_record.go` (run
  rows and apply budget) and `run_plan_render.go`.

No behavior change; tests now inject options and a scripted runner.

## Run-set converge members are finalized like standalone runs (fix)

`executePreparedMutationPlan` called the converge loop directly. A set
converge therefore never evaluated the member's checks, never wrote its verdict
to the model's status row, and never promoted its `converging` resources to
`clean` — all of which `pudl run --converge` does.

`finalizeRun(runFinalizeInput, *RunReport, *runFinishState, runErr)
(runFinalization, error)` is now the single conclusion: checks, verdict,
model-row status (with the `--only` and check-demotion notes), and promotion.
Standalone runs call it through `concludeRun`; set members call it through
`executeMutationMember`. `runConclusion(state, runErr)` builds the run row for
both paths.

Behavior changes for `pudl run set --converge` members:

- Checks run after the member converges; results are in the member report.
- The model row records the member's verdict, and is cleared to `unknown`
  before mutation starts (as a standalone converge does), so a crash cannot
  leave a stale `clean`.
- A verified clean promotes the model's `converging` resources.
- A failing fail-severity check demotes `clean` to `drifted` and fails the
  member. Like any failed member, that stops the set's later mutations
  (dependents blocked, others cancelled).
- A failure to evaluate checks fails the member instead of aborting the set.

Tests: `cmd/run_set_finalize_test.go` (clean member: checks, model row,
promotion, run row; failing check: member failed, verdict demoted, note).

## `--detailed-exitcode` (feature)

Opt-in on `pudl run` and `pudl run set`: exit 0 clean, 2 findings (drift,
pending `--dry-run` changes, or a failing fail-severity check with no other
error), 1 error. Default exit behavior is unchanged.

- `cmd/run_exit.go`: `exitCodeError{code, err}`, `exitCodeFor(err) int`,
  `reportHasFindings(*RunReport) bool`, `detailedRunExit(report, err) error`,
  `detailedRunSetExit(*runSetResult, err) error`, `silenceBareExit(cmd, err)`.
- `errFailSeverityChecks` is the sentinel for "phases succeeded, a
  fail-severity check did not pass".
- `executeRun` returns its `*RunReport`; `executeRunSet` returns a
  `*runSetResult{report, findings}`.
- `root.go` exits with `exitCodeFor(err)`: an `exitCodeError`'s code, else a
  `PUDLError`'s `GetExitCode()`, else 1. **Behavior change:** `RunE` commands
  returning a `PUDLError` (e.g. `schema new`, `schema reinfer`,
  `identity migrate`) now exit with that error's code (2, 74, 77, 78) instead
  of always 1, matching the `Run` commands that already did.
- Under `--detailed-exitcode` every error exits 1, so 2 always means findings.

Tests: `cmd/run_exit_test.go` (mapping table, run-set cases, real observe and
converge sets). Verified end to end with the git-inventory walkthrough: the
changed observation replay exits 0 by default and 2 with the flag.

Docs: `docs/cli-reference.md` (`pudl run` exit status table, `pudl run set`
flag and member finalization).
